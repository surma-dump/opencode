# Skill Discovery Server API

This document describes the HTTP API that a skill discovery server must implement to work with OpenCode's dynamic skill discovery feature.

---

## Overview

When dynamic skill discovery is enabled, OpenCode sends a task description to your server and expects a list of relevant skills in return. This allows you to:

- Dynamically determine which skills are relevant based on context
- Use semantic search, LLMs, or custom logic to match tasks to skills
- Centralize skill management across multiple OpenCode instances
- Integrate with external knowledge bases or documentation systems

---

## Configuration

Enable the skill discovery server in your `opencode.json`:

```jsonc
{
  "skill_discovery": {
    "enabled": true,
    "endpoint": "https://api.example.com/skills/discover",
    "description_prompt": "Summarize the task: {conversation}",
    "cache_ttl": 300000,
    "headers": {
      "Authorization": "Bearer {env:SKILL_API_TOKEN}",
    },
    "timeout": 10000,
    "fallback_to_filesystem": false,
  },
}
```

## API Specification

### Endpoint

**`POST /skills/discover`** (or your configured endpoint path)

### Request

#### Headers

- `Content-Type: application/json`
- Custom headers from `skill_discovery.headers` config (e.g., `Authorization`)

#### Body

```json
{
  "task": "string"
}
```

**Fields:**

- `task` (string, required): A concise 1-2 sentence description of the current task, generated by OpenCode's LLM based on the conversation history.

#### Example Request

```json
{
  "task": "Implement JWT authentication for a Node.js Express API with refresh tokens and secure cookie handling"
}
```

### Response

#### Success (200 OK)

Return a JSON object with a `skills` array. Skills can be provided in two formats:

##### Format 1: Inline Content (Recommended)

Provide complete skill data directly in the response:

```json
{
  "skills": [
    {
      "name": "jwt-auth",
      "description": "JWT authentication implementation guide for Express.js",
      "content": "## JWT Authentication\n\nThis skill covers...\n\n### Setup\n\n..."
    },
    {
      "name": "express-security",
      "description": "Security best practices for Express.js applications",
      "content": "## Express Security\n\n..."
    }
  ]
}
```

**Fields:**

- `name` (string, required): Unique identifier for the skill (alphanumeric, hyphens, underscores)
- `description` (string, required): Short description of what the skill covers
- `content` (string, required): Full markdown content of the skill

##### Format 2: File Paths

Provide file paths that OpenCode will load:

```json
{
  "skills": ["/path/to/skills/jwt-auth/SKILL.md", "/path/to/skills/express-security/SKILL.md"]
}
```

Each file must be a valid skill file with frontmatter:

```markdown
---
name: jwt-auth
description: JWT authentication implementation guide
---

## JWT Authentication

...
```

**Note:** File paths require OpenCode to have filesystem access to the specified locations.

##### Mixed Format

You can mix both formats:

```json
{
  "skills": [
    {
      "name": "jwt-auth",
      "description": "JWT authentication guide",
      "content": "..."
    },
    "/path/to/skills/express-security/SKILL.md"
  ]
}
```

#### Error Responses

##### 400 Bad Request

Invalid request format:

```json
{
  "error": "Invalid request",
  "message": "Missing required field: task"
}
```

##### 401 Unauthorized

Authentication failed:

```json
{
  "error": "Unauthorized",
  "message": "Invalid or missing API token"
}
```

##### 500 Internal Server Error

Server error:

```json
{
  "error": "Internal server error",
  "message": "Failed to process skill discovery request"
}
```

## Behavior

### Request Flow

1. User sends a message to OpenCode
2. OpenCode generates a task description using its LLM
3. OpenCode sends the task description to your server
4. Your server returns relevant skills
5. OpenCode caches the skills for the session (default: 5 minutes)
6. Skills appear in the agent's skill tool description

### Caching

- Skills are cached per-session with a configurable TTL (`cache_ttl`)
- Cache is invalidated when the agent uses the `update_skill_context` tool
- Different sessions with the same task description will make separate requests (per-session caching)

### Fallback

If `fallback_to_filesystem: true`:

- On HTTP error or timeout, OpenCode falls back to filesystem-based skill discovery
- Useful for development or unreliable network conditions

If `fallback_to_filesystem: false` (default):

- On HTTP error, no skills are available to the agent
- Agent sees "No skills are currently available" message

## Implementation Examples

### Simple Static Mapping

```javascript
// Node.js Express example
app.post("/skills/discover", (req, res) => {
  const { task } = req.body

  if (!task) {
    return res.status(400).json({
      error: "Bad Request",
      message: "Missing required field: task",
    })
  }

  const keywords = task.toLowerCase()
  const skills = []

  if (keywords.includes("auth") || keywords.includes("jwt")) {
    skills.push({
      name: "jwt-auth",
      description: "JWT authentication implementation guide",
      content: "## JWT Authentication\n\n...",
    })
  }

  if (keywords.includes("database") || keywords.includes("sql")) {
    skills.push({
      name: "database-design",
      description: "Database design best practices",
      content: "## Database Design\n\n...",
    })
  }

  res.json({ skills })
})
```

### Semantic Search with Embeddings

```python
# Python FastAPI example with vector search
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import numpy as np
from sentence_transformers import SentenceTransformer

app = FastAPI()
model = SentenceTransformer('all-MiniLM-L6-v2')

# Pre-computed embeddings for your skills
SKILLS = [
    {
        "name": "jwt-auth",
        "description": "JWT authentication implementation",
        "content": "...",
        "embedding": model.encode("JWT authentication tokens refresh cookies")
    },
    # ... more skills
]

class DiscoveryRequest(BaseModel):
    task: str

@app.post('/skills/discover')
async def discover_skills(request: DiscoveryRequest):
    # Generate embedding for task
    task_embedding = model.encode(request.task)

    # Compute similarity scores
    scores = []
    for skill in SKILLS:
        similarity = np.dot(task_embedding, skill['embedding'])
        scores.append((similarity, skill))

    # Return top 5 most relevant skills
    scores.sort(reverse=True, key=lambda x: x[0])
    top_skills = [
        {
            "name": skill["name"],
            "description": skill["description"],
            "content": skill["content"]
        }
        for score, skill in scores[:5]
        if score > 0.3  # Threshold
    ]

    return {"skills": top_skills}
```

### LLM-Based Selection

```typescript
// TypeScript with OpenAI
import { OpenAI } from "openai"
import express from "express"

const app = express()
const openai = new OpenAI()

const AVAILABLE_SKILLS = [
  { name: "jwt-auth", description: "JWT authentication", content: "..." },
  { name: "react-hooks", description: "React hooks patterns", content: "..." },
  // ... more skills
]

app.post("/skills/discover", async (req, res) => {
  const { task } = req.body

  const prompt = `
Given this task: "${task}"

Select relevant skills from this list:
${AVAILABLE_SKILLS.map((s) => `- ${s.name}: ${s.description}`).join("\n")}

Return only the skill names as a JSON array.
`

  const response = await openai.chat.completions.create({
    model: "gpt-4o-mini",
    messages: [{ role: "user", content: prompt }],
    response_format: { type: "json_object" },
  })

  const selectedNames = JSON.parse(response.choices[0].message.content).skills
  const skills = AVAILABLE_SKILLS.filter((s) => selectedNames.includes(s.name))

  res.json({ skills })
})
```

### Database-Backed Skills

```go
// Go with PostgreSQL
package main

import (
    "database/sql"
    "encoding/json"
    "net/http"
    _ "github.com/lib/pq"
)

type DiscoveryRequest struct {
    Task string `json:"task"`
}

type Skill struct {
    Name        string `json:"name"`
    Description string `json:"description"`
    Content     string `json:"content"`
}

func discoverSkills(w http.ResponseWriter, r *http.Request) {
    var req DiscoveryRequest
    json.NewDecoder(r.Body).Decode(&req)

    // Full-text search in PostgreSQL
    rows, err := db.Query(`
        SELECT name, description, content
        FROM skills
        WHERE to_tsvector('english', name || ' ' || description || ' ' || tags)
              @@ plainto_tsquery('english', $1)
        ORDER BY ts_rank(to_tsvector('english', name || ' ' || description),
                         plainto_tsquery('english', $1)) DESC
        LIMIT 10
    `, req.Task)

    if err != nil {
        http.Error(w, err.Error(), 500)
        return
    }
    defer rows.Close()

    skills := []Skill{}
    for rows.Next() {
        var skill Skill
        rows.Scan(&skill.Name, &skill.Description, &skill.Content)
        skills = append(skills, skill)
    }

    json.NewEncoder(w).Encode(map[string]interface{}{
        "skills": skills,
    })
}
```

## Best Practices

### Performance

- **Response time**: Aim for < 1 second. OpenCode has a default 5-second timeout.
- **Caching**: Cache skill content in memory or use a fast database.
- **Limit results**: Return 3-10 most relevant skills, not all possible matches.

### Security

- **Authentication**: Use the `headers` config to require API keys or OAuth tokens.
- **Rate limiting**: Protect your endpoint from abuse.
- **Input validation**: Sanitize the task description, though OpenCode generates it.

### Skill Content

- **Markdown format**: Use standard markdown with code blocks.
- **Conciseness**: Keep skills focused and practical (1-3 pages).
- **Examples**: Include concrete code examples.
- **Context**: Skills can reference files using relative paths from the skill's base directory.

### Error Handling

- Return appropriate HTTP status codes
- Provide helpful error messages
- Log errors for debugging
- Consider graceful degradation (return partial results)

## Troubleshooting

### Skills not appearing

- Check OpenCode logs for HTTP errors
- Verify endpoint is reachable from OpenCode's environment
- Confirm response format matches specification
- Check authentication headers

### Slow responses

- Add logging to measure each step (embedding, search, etc.)
- Consider caching task→skills mappings
- Use faster embedding models or simpler matching logic
- Pre-compute embeddings or indexes

### Wrong skills returned

- Log the task description OpenCode sends
- Tune your similarity thresholds
- Add logging for matching logic
- Test with various task descriptions

## Advanced Features

### Context-Aware Discovery

Include additional context in your request by extending the API:

```json
{
  "task": "Implement authentication",
  "context": {
    "language": "typescript",
    "framework": "express",
    "files": ["src/auth.ts", "src/user.ts"]
  }
}
```

Note: This requires customization of OpenCode's task description generation.

### Skill Dependencies

Return skills with dependency information:

```json
{
  "skills": [
    {
      "name": "jwt-auth",
      "description": "JWT authentication",
      "content": "...",
      "requires": ["express-setup", "typescript-basics"]
    }
  ]
}
```

OpenCode doesn't currently handle dependencies, but you can include them in the skill content.

### Versioning

Include version information for skill evolution:

```json
{
  "skills": [
    {
      "name": "jwt-auth",
      "version": "2.1.0",
      "description": "JWT authentication (updated for Node 20)",
      "content": "..."
    }
  ]
}
```

## Example Skill Content

Skills should be well-structured markdown documents:

````markdown
## JWT Authentication in Express.js

This skill covers implementing secure JWT authentication in an Express.js application.

### Prerequisites

- Node.js 18+
- Express.js installed
- Basic understanding of HTTP authentication

### Setup

Install required packages:

```bash
npm install jsonwebtoken bcrypt cookie-parser
```
````

### Implementation

#### 1. Generate tokens

```typescript
import jwt from "jsonwebtoken"

function generateToken(userId: string): string {
  return jwt.sign({ userId }, process.env.JWT_SECRET!, { expiresIn: "15m" })
}
```

#### 2. Verify tokens

```typescript
function verifyToken(token: string): { userId: string } | null {
  try {
    return jwt.verify(token, process.env.JWT_SECRET!) as { userId: string }
  } catch {
    return null
  }
}
```

### Security Best Practices

- Use strong secrets (min 32 characters)
- Set appropriate expiration times
- Use httpOnly cookies for tokens
- Implement refresh token rotation
- Add rate limiting to login endpoints

### Common Issues

**Issue**: "JsonWebTokenError: invalid signature"
**Solution**: Verify JWT_SECRET matches between generation and verification

**Issue**: Tokens expire too quickly
**Solution**: Implement refresh token mechanism (see refresh-token skill)

